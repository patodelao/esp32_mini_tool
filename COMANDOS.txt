================================================================================
  REFRI / opendoor_alarm   (ESP-IDF S3)  ***EL BROKER - FLASHEAR PRIMERO***
  IP 192.168.1.108    OTA key: refri-ota
================================================================================
  cd C:\Users\alons\Documents\Proyectos_ESP32\esp32_mini_tool\opendoor_alarm

  Compilar:
    idf.py build

  Flashear por USB  (reemplaza COM11 por tu puerto):
    idf.py -p COM11 flash

  Monitor serie  (Ctrl+] para salir) / flash+monitor juntos:
    idf.py -p COM11 monitor
    idf.py -p COM11 flash monitor

  Flashear por WiFi (OTA), con el nodo ya en la red:
    curl -X POST --data-binary "@build/opendoor_alarm.bin" "http://192.168.1.108/update?key=refri-ota"

  Al bootear, en el monitor tiene que aparecer:
    "Broker MQTT escuchando en mqtt://0.0.0.0:1883"
  y antes, el WiFi conectando con su IP. Si dice SSID "cambiame" -> falta secrets.h.

================================================================================
  PIEZA / esp8266_sensor   (PlatformIO, NO ESP-IDF)
  IP 192.168.1.109    OTA key: pieza-ota
================================================================================
  cd C:\Users\alons\Documents\Proyectos_ESP32\esp32_mini_tool\esp8266_sensor

  Compilar (sin flashear):
    pio run -e nodemcuv2

  Flashear por USB  (reemplaza COM11 por tu puerto):
    pio run -e nodemcuv2 -t upload --upload-port COM11

  Monitor serie:
    pio device monitor -p COM11 -b 115200

  Flashear por WiFi (OTA)  -- OJO: va la IP, NO un COM:
    pio run -e pieza_ota -t upload --upload-port 192.168.1.109

  * nodemcuv2 = USB ;  pieza_ota = WiFi. Si a un upload OTA le pasas un COM,
    da "getaddrinfo failed" (espota espera una IP, no un puerto serie).
  * Si NO ponor -e, PlatformIO corre los DOS entornos; por eso conviene el -e.

================================================================================
  VER LOS SENSORES EN EL CELULAR  (app MQTT, sin firmware)
  Gadgetbridge NO sirve para esto (solo grafica fitness). Se usa una app MQTT.
================================================================================
  App: "IoT MQTT Panel" (Android, gratis; tiene widget Line Graph).
  El celu tiene que estar en el MISMO WiFi que los nodos.

  Conexion (Add connection):
    Broker/Host : 192.168.1.108      (el refri = broker)
    Port        : 1883
    Auth        : ninguno (anonimo)   TLS: off
    Client ID   : cualquiera (ej. celu-alonso)

  Paneles (tipo Line Graph, uno por topic; el valor es un numero -> grafica solo):
    labo/sensor/pieza/suelo         humedad suelo (%)
    labo/sensor/pieza/temp          temp aire pieza (C)
    labo/sensor/pieza/hum           humedad aire (%)
    labo/sensor/refri/abierta_seg   segundos puerta abierta
    labo/sensor/pi/temp             temp CPU RetroPi (C)
    labo/sensor/pi/cpu              uso CPU (%)
    labo/sensor/<nodo>/rssi         senal WiFi (dBm)   [<nodo>: pieza/refri/pi/minitool/cam]
    labo/sensor/#                   TODOS los sensores de una

  OJO:
    - Requiere que el BROKER (opendoor .108) este arriba. Si la app no conecta,
      revisar opendoor con el "CHEQUEO RAPIDO" de mas arriba.
    - Los graficos son EN VIVO (mientras la app este abierta). Los retenidos dan
      el ultimo valor al abrir, no el historial. Para historial real en el celu:
      Grafana en la Pi leyendo del broker (proyecto aparte).
